Use the lookup endpoints when you only need to check a Nigerian BVN or NIN and don't need a full verification: no workflow, no capture screens. Both endpoints use the same [API key headers](/api-reference/introduction#authentication) as the rest of the API.

| Lookup | Endpoint |
|---|---|
| [BVN match](#match-details-against-a-bvn) | `POST /api/v1/lookups/bvn/match` |
| [NIN lookup](#look-up-a-nin) | `POST /api/v1/lookups/nin` |

<Warning>
Every successful response is charged to the organization's credits. A lookup that fails is never charged. Read [BVN and NIN lookups](/billing#bvn-and-nin-lookups) on the billing page before you go live.
</Warning>

## Match details against a BVN

Send the BVN together with a name, date of birth and mobile number. The response says, for each of the three, whether it matches the BVN. The BVN holder's record is never returned. All four fields are required.

| Field | Required | Format |
|---|---|---|
| `bvn` | Yes | Exactly 11 digits |
| `name` | Yes | 2 to 200 characters: letters, spaces, dots, apostrophes and hyphens. Case and punctuation don't affect the match. |
| `dateOfBirth` | Yes | `YYYY-MM-DD`, in the past |
| `mobileNumber` | Yes | A Nigerian number: `08142223149`, `2348142223149` or `+2348142223149` |

<CodeGroup>
```bash cURL
curl -X POST https://api.urtentic.com/api/v1/lookups/bvn/match \
  -H "X-CLIENT-ID: ${URTENTIC_CLIENT_ID}" \
  -H "Authorization: Bearer ${URTENTIC_SECRET_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "bvn": "22222222226",
    "name": "OLATUNDE JOSIAH OGUNBOYEJO",
    "dateOfBirth": "1993-04-27",
    "mobileNumber": "08142223149"
  }'
```

```javascript JavaScript
const response = await fetch("https://api.urtentic.com/api/v1/lookups/bvn/match", {
  method: "POST",
  headers: {
    "X-CLIENT-ID": process.env.URTENTIC_CLIENT_ID,
    Authorization: `Bearer ${process.env.URTENTIC_SECRET_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({
    bvn: "22222222226",
    name: "OLATUNDE JOSIAH OGUNBOYEJO",
    dateOfBirth: "1993-04-27",
    mobileNumber: "08142223149",
  }),
});

if (!response.ok) {
  const error = response.status === 401 ? { code: "UNAUTHORIZED" } : await response.json();
  throw new Error(`BVN match failed with HTTP ${response.status} (${error.code})`);
}
const { match } = await response.json();
console.log(match.name.status, match.dateOfBirth.status, match.mobileNumber.status);
```

```python Python
import os
import requests

response = requests.post(
    "https://api.urtentic.com/api/v1/lookups/bvn/match",
    headers={
        "X-CLIENT-ID": os.environ["URTENTIC_CLIENT_ID"],
        "Authorization": f"Bearer {os.environ['URTENTIC_SECRET_KEY']}",
    },
    json={
        "bvn": "22222222226",
        "name": "OLATUNDE JOSIAH OGUNBOYEJO",
        "dateOfBirth": "1993-04-27",
        "mobileNumber": "08142223149",
    },
    timeout=30,
)

if not response.ok:
    code = response.json().get("code") if response.content else "UNAUTHORIZED"
    raise RuntimeError(f"BVN match failed with HTTP {response.status_code} ({code})")
match = response.json()["match"]
print(match["name"]["status"], match["dateOfBirth"]["status"], match["mobileNumber"]["status"])
```

```php PHP
<?php
$curl = curl_init("https://api.urtentic.com/api/v1/lookups/bvn/match");
curl_setopt_array($curl, [
    CURLOPT_POST => true,
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_TIMEOUT => 30,
    CURLOPT_HTTPHEADER => [
        "X-CLIENT-ID: " . getenv("URTENTIC_CLIENT_ID"),
        "Authorization: Bearer " . getenv("URTENTIC_SECRET_KEY"),
        "Content-Type: application/json",
    ],
    CURLOPT_POSTFIELDS => json_encode([
        "bvn" => "22222222226",
        "name" => "OLATUNDE JOSIAH OGUNBOYEJO",
        "dateOfBirth" => "1993-04-27",
        "mobileNumber" => "08142223149",
    ]),
]);
$body = curl_exec($curl);
$status = curl_getinfo($curl, CURLINFO_HTTP_CODE);
curl_close($curl);

if ($body === false || $status !== 200) {
    $code = $body ? (json_decode($body, true)["code"] ?? "UNKNOWN") : "NO_RESPONSE";
    throw new RuntimeException("BVN match failed with HTTP $status ($code)");
}
$match = json_decode($body, true)["match"];
echo $match["name"]["status"], " ", $match["dateOfBirth"]["status"], " ", $match["mobileNumber"]["status"];
```

```java Java
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;

String body = """
    {"bvn":"22222222226","name":"OLATUNDE JOSIAH OGUNBOYEJO","dateOfBirth":"1993-04-27","mobileNumber":"08142223149"}
    """;
HttpRequest request = HttpRequest.newBuilder(URI.create("https://api.urtentic.com/api/v1/lookups/bvn/match"))
    .timeout(Duration.ofSeconds(30))
    .header("X-CLIENT-ID", System.getenv("URTENTIC_CLIENT_ID"))
    .header("Authorization", "Bearer " + System.getenv("URTENTIC_SECRET_KEY"))
    .header("Content-Type", "application/json")
    .POST(HttpRequest.BodyPublishers.ofString(body))
    .build();

HttpResponse<String> response = HttpClient.newHttpClient().send(request, HttpResponse.BodyHandlers.ofString());
if (response.statusCode() != 200) {
    throw new IllegalStateException("BVN match failed with HTTP " + response.statusCode() + ": " + response.body());
}
System.out.println(response.body());
```
</CodeGroup>

```json 200 response
{
  "bvn": "***2226",
  "match": {
    "name": { "status": "FULL_MATCH", "score": 100 },
    "dateOfBirth": { "status": "NO_MATCH" },
    "mobileNumber": { "status": "FULL_MATCH" }
  }
}
```

The BVN comes back masked. Each detail has a `status`:

| `status` | Meaning |
|---|---|
| `FULL_MATCH` | The detail matches the BVN |
| `PARTIAL_MATCH` | The detail is close but not exact |
| `NO_MATCH` | The detail doesn't match |

The name also has a `score` from 0 to 100, or `null` when no score is available. Decide for yourself what counts as a pass: for example, require `FULL_MATCH` on the date of birth and accept `FULL_MATCH` or `PARTIAL_MATCH` on the name.

<Note>
A `NO_MATCH` is a successful response, so it is charged. A request that is refused (`422`) is not.
</Note>

## Look up a NIN

Send the 11-digit NIN. The response is the record on file. To also check details against it, send them in `match`: see [Match details against a NIN](#match-details-against-a-nin).

| Field | Required | Format |
|---|---|---|
| `nin` | Yes | Exactly 11 digits |

<CodeGroup>
```bash cURL
curl -X POST https://api.urtentic.com/api/v1/lookups/nin \
  -H "X-CLIENT-ID: ${URTENTIC_CLIENT_ID}" \
  -H "Authorization: Bearer ${URTENTIC_SECRET_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"nin": "94646622685"}'
```

```javascript JavaScript

    Authorization: `Bearer ${process.env.URTENTIC_SECRET_KEY}`,

```

### Match details against a NIN

Add a `match` object with a name, a date of birth, a mobile number, or any of them, the response is the same record as before, with a `match` added that says how each one compares with it. `match` has the same shape as in a [BVN match](#match-details-against-a-bvn). Only the details you send are compared, and the others are left out of `match`.

| Field | Required | Format |
|---|---|---|
| `match.name` | No | 2 to 200 characters: letters, spaces, dots, apostrophes and hyphens. Case, punctuation and word order don't affect the match. |
| `match.dateOfBirth` | No | `YYYY-MM-DD`, in the past |
| `match.mobileNumber` | No | A Nigerian number: `08107248890`, `2348107248890` or `+2348107248890` |

```bash cURL
curl -X POST https://api.urtentic.com/api/v1/lookups/nin \
  -H "X-CLIENT-ID: ${URTENTIC_CLIENT_ID}" \
  -H "Authorization: Bearer ${URTENTIC_SECRET_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "nin": "94646622685",
    "match": {
      "name": "BENJAMIN WILES",
      "dateOfBirth": "1996-10-08",
      "mobileNumber": "08107248890"
    }
  }'
```

```json 200 response
{
  "nin": "***2685",
  "firstName": "BENJAMIN",
  "middleName": "CHUKS",
  "lastName": "WILES",
  "dateOfBirth": "1996-10-08",
  "gender": "OTHER",
  "mobileNumber": "+2348107248890",
  "match": {
    "name": { "status": "PARTIAL_MATCH", "score": 80 },
    "dateOfBirth": { "status": "FULL_MATCH" },
    "mobileNumber": { "status": "FULL_MATCH" }
  }
}
```

The date of birth and the mobile number are either `FULL_MATCH` or `NO_MATCH`. The name is compared word by word, in any order: a middle name left out or a slightly different spelling is a `PARTIAL_MATCH`, with a `score` from 0 to 100. A request with an empty `match` is the same as one without it: no `match` in the response.

<Note>
A match is charged like any other lookup, whatever the result.
</Note>

## Errors and what is charged

| Status | `code` | What to do | Charged? |
|---|---|---|---|
| `400` | `VALIDATION_ERROR` | Fix the fields listed in `errors` | No |
| `401` | none (no body) | Check the API key and client ID | No |
| `402` | `CREDITS_REQUIRED` | Buy credits, then retry | No |
| `422` | `IDENTITY_LOOKUP_REJECTED` | The number or details were refused. Correct them: retrying the same request gives the same answer | No - refunded |
| `429` | `RATE_LIMIT_EXCEEDED` | Wait, then retry. The limit is 60 lookups a minute for the organization. | No |
| `502` | `IDENTITY_LOOKUP_UNAVAILABLE` | Retry after a short wait | No - refunded |

Only a `200` is charged. See [Billing and usage](/billing#bvn-and-nin-lookups) for refunds and what shows in your credit activity.

<Warning>
BVNs and NINs are personal data. Don't log them or the lookup results in plain text, and don't retry a `422` in a loop: each attempt counts towards your rate limit.
</Warning>
